Before we build anything else, I want to show you the full map. Because if you don't know where everything lives and why, you'll build files that duplicate each other, contradict each other, or don't get used at all. Today is the one day in this curriculum where we don't produce a file. We just understand the architecture. Think of it as reading the blueprint before construction starts. Everything we build from Day 5 onwards will make more sense with this mental picture in place. There are five types of files in a well-built AI agent system. They each do a different job. Here's how I think about them. First is claude.md. This is the operating manual. It tells the agent what it's for, what tools it has access to, what the boundaries are, how to behave in different situations. If the agent is an employee, claude.md is the employee handbook. It covers process, not personality. Second is soul.md. This is the personality layer. If claude.md is the brain — what the agent knows — soul.md is who it is. Your values, your communication preferences, your decision-making style, your risk tolerance. The agent reads this file to understand not just what to do but how you'd want it done. We build this across Days 8 to 14. Third are knowledge bases. These are context files about specific domains. Your industry knowledge. Your company information. Your current projects. The market conditions your trading agent needs to understand. The client relationship context your communications agent needs. Knowledge bases are the reference library the agent pulls from when making decisions. We start building these from Day 15. Fourth are skills files. These are individual task modules — discrete things the agent can do. A skill might be: draft a YouTube description in this format, or run a risk assessment using these criteria, or summarise a document in this structure. Skills are separate from the main agent configuration because they can be called individually, updated without touching the whole system, and reused across different agents. Fifth are memory files. These are dynamic. They update as the agent learns things or as your situation changes. A memory file might store: last week's trading positions, recent client interactions, notes from calls, things you've told the agent to remember. Memory is the only part of the system that's genuinely alive — everything else is static until you edit it. Here's how they connect. The agent reads claude.md every time to understand its role. It reads soul.md to understand your preferences. It pulls from knowledge bases when it needs context on a specific topic. It calls skills when it needs to execute a specific task. And it writes to memory files when it learns something new. The mistake most people make is trying to put everything in one place. They write a huge claude.md that contains their values, their knowledge, their skills, their preferences, all mixed together. That creates a file that's too long, too slow to process, and impossible to update without breaking something. The separation matters. Each file should do one job.
